# Технические истории

ТИ-01. Глоссарий хранится в формате `JSON`(`JSONL`)
> Формат  `JSON`(`JSONL`) с жёсткой схемой для хранения локальной версии переводчика (в рамках MVP, до развития в облачный продукт)
> Глоссарий формируется один раз на документ.
> По окончанию формирования глоссария модель освобождает память под транслятор.

ТИ-02. Когда используется модель `TranslateGemma`, то применяется строгий шаблон промпта
> При отклонении от шаблона качество падает, т.к. модель переходит в режим диалога.
> Шаблон: "Translate this from {src} to {tgt}: ..."

ТИ-03. Когда выполняется чанкование текста из pdf, размер одного чанка не должен превышать 2000 символов.
> Для ряда моделей типа `TranslateGemma` это техническое ограничение.
> Для остальных моделей может быть потерян контекст при большом размере чанка.
> Реально размер может быть ниже, порядка 500-1500.
> Возможно добавить ТИ для добавления в `verify` этапа проверки "количество предложений вход ≈ выход

ТИ-04. Когда тематика выбрана в `dropdown`, модель должна подниматься в фоне
> параллельно с `ingest`
> до нажатия кнопки начала перевода

ТИ-05. Когда пользователь выбрал тематику перевода, отображается надпись "модель готова"
> UX-честность
> пользователь видит, почему первые секунды ничего не происходит
> при выборе тематики меняется значение в конфигурационном файле `themes.yaml`
> код при этом не задействован
> повторный выбор той же тематики не вызывает повторно загрузку - идемпотентность
