ФТ-02. Для распознавания доступен документ в форматах `pdf`

ФТ-03. Для распознавания доступен документ в текстовом формате
```txt
К текстовым форматам относятся `txt`, `md`, `ascii`
```

ФТ-04. Перевод осуществляется с помощью LLM

ФТ-05. Приложение ориентировано на перевод технической документации на русский язык
```txt
Предположительно в большинстве случаев язык оригинала документа  -- английский.
```

ФТ-06. Изображения в переводимых документах должны извлекаться и вставляться в перевод без изменений

ФТ-07. Перед выполнением перевода должен формироваться глоссарий документа
```txt
Глоссарий содержит термины и определения непосредственно из переводимого документа, а также термины, которые могут встерчаться в документе, но иметь двузначный перевод.
```
Глоссарий -- детерминированное хранилище `термин` -> `утверждённый перевод` с метаданными (источник-раздел, дата, статус). Хранить в `JSON`, не в векторном хранилище.

Глоссарий ≠ термины из текста документа

ФТ-08.  После формирования глоссария пользователь в него может вносить изменения
> Изменения могут вноситься до момента начала перевода всего текста документа.
> По окончанию внесения изменений активируется кнопка запуска перевода. 
> До окончания внесения изменений в глоссарий кнопка запуска перевода неактивна. Если пользователь не вносит изменений в глоссарий, он должен всё равно подтвердить своё решение нажатием кнопки "`Принять глоссарий`".

ФТ-09. Опционально возможна постобработка для вычитки и улучшения стиля лёгкой моделью

ФТ-10. В ходе перевода должна выполняться чистка файла от "мусорных" данных
> footer
> header

ФТ-11. Должен осуществляться запуск вызываемых моделей и приостановка простаиваемых
> Для эффективного расходования ресурсов
> `RoT` -- "поднять по запросу, выгрузить старый"

ФТ-12. Для локального инференса должны использоваться доступные модели

  - `translategemma-12b-it-8bit` -- технический перевод (регламенты, стандарты, 3gpp, RFC)
  - `translategemma-4b-it-4bit` -- предпросмотр страницы до похода в тяжёлую модель

ФТ-13. Извлечение структуры из pdf до перевода
> Выбор способа извлечения текста в зависимости от `OCR`/`Layout`

ФТ-14. Переведённый документ должен быть выгружен в читаемый формат:

К таковым относятся:
  - LaTeX
  - Markdown
  - pdf

> Выгрузка в pdf может осуществляться из md и LaTeX стандартными утилитами

ФТ-15. Спецсодержимое должно помечаться Docling-тегами
> Помечать как `no_translate`
> Как вариант -- оборачивать в protect-токены

Спецсодержимое:
  - таблицы, 
  - формулы, 
  - ASN.1
  - диаграммы 

ФТ-16. Приложение должно извлекать изображения "**как есть**" и возвращать их в переведённый документ
> См. ФТ-15
> Изображение = ресурс + плейсхолдер
> Схема работы с изображениями -- разработать по шагам!!! Вот ориентировочный план:
  - парсинг
  - защита от перевода - пометка тегом `no_translate`
  - хранение связи в State LangGraph
  - сборка в md/LaTeX/pdf
> рендер вместо извлечения

ФТ-17. Сформировать и вести в контроле версий глоссарий тематики
В рамках MVP возможно преждевременно. Далее перспективно. Использовать такой глоссарий в качестве образца.
