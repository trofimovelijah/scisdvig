# Пользовательские сценарии
## UR-01. Пользователь должен иметь возможность загружать документ через веб-интерфейс

## UR-02. При невозможности загрузить документ пользователю должна возвращаться удобочитаемая информация о причине отсутствия возможности загрузки
```txt
К таковым относятся:
  - превышение размера документа
  - не поддерживаемый формат документа
```

## UR-03. Допустимый размер загружаемого документа ограничен `200 Mb`.

## UR-04. Пользователь должен видеть прогресс выполнения обработки документа

## UR-05. Пользователю возвращается сообщение при ошибке выполнения этапов перевода документа
> Ошибка должна описывать конкретное поведение на каждом конкретном этапе перевода.
> Язык ошибки -- русский. 
> Отладочная информация содержится.

## UR-06. Пользователь перед переводом выбирает из выпадающего списка предметную область/тематику перевода
> На момент запуска MVP достаточно одной тематики -- технической
> Перед переводом должна выполняться классификация тематики текста для выбора оптимальной модели или подхода

## UR-07. Пользователь может запрашивать превью перевода
> опционально
> в рамках MVP не на первом месте

## UR-08. Пользователь видит расход токенов по этапам перевода
Статус: `draft`

Формулировка:
Как пользователь-переводчик, я хочу видеть количество входных и выходных токенов по каждому этапу, использующему LLM, чтобы оценивать расход токенов при переводе документа.

Критерии приёмки:
- После завершения этапа в интерфейсе отображается расход токенов по всем вызовам LLM на этом этапе, включая повторные попытки.
- Данные представлены в таблице с указанием этапа, модели, способа запуска, количества входных и выходных токенов и их суммы.
- Если на этапе использовались разные модели или способы запуска, для каждой комбинации отображается отдельная строка.
- Если счётчики недоступны хотя бы для одного вызова, расход помечается как неполный; отсутствующие значения не заменяются нулями.
- Отображается общий расход токенов за текущий запуск перевода с указанием неполноты данных, если она есть.

Табличный вид:
| Этап | Используемая модель | Способ запуска | Входные токены | Выходные токены | Всего токенов | Полнота данных |
|------|---------------------|----------------|---------------:|----------------:|--------------:|---------------:|
|      |                     |                |                |                 |               |                |
| Итого |                    |                |                |                 |               |                |

Проверка:
1. Выполнить тестовый перевод с заранее известными счётчиками, несколькими этапами и повторным вызовом LLM.
2. Убедиться, что после завершения каждого этапа появляется соответствующая строка, а значения совпадают с суммой счётчиков его вызовов.
3. Проверить разделение строк при использовании разных моделей или способов запуска.
4. Проверить общий расход за запуск перевода.
5. Повторить проверку с вызовом без счётчиков: убедиться, что данные отмечены как неполные и отсутствующие значения не заменены нулями.
