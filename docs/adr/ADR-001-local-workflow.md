# ADR-001. Локальное модульное приложение

Статус: `proposed`
Дата предложения: 2026-11-14
Итерация: I1 — первый сквозной локальный запуск
Основания: `F-REQ-04/06`, `NF-REQ-02/04`, `CON-1/4`
Заменяет: нет

## Контекст

Обработка включает документы, вызовы модели, решения пользователя и экспорт. Изменения должны проверяться небольшими частями.
Смена runtime не должна требовать переписывания UI и перевода.

Связанные требования пока `draft`.
Этот ADR не повышает их статус автоматически.

## Варианты

1. Один модуль для UI, PDF, промптов и workflow.
2. Модульное приложение с явными контрактами.
3. Отдельные сервисы для этапов.

## Критерии выбора

Проверка без реальной LLM, замена runtime, простота локального запуска и локализация ошибок.

## Предлагаемое решение

Выбрать вариант 2.

LangGraph отвечает за переходы, но не содержит всю логику.
Разделить документы, перевод, адаптер модели, хранение, экспорт и UI.
Передавать между этапами структурированные данные и ссылки на артефакты, а не бинарный PDF целиком.
Не вводить отдельного агента на каждый узел.

Модель, runtime и контейнеризация этим ADR не выбираются.

## Последствия

Плюсы: 
  - независимые тесты,
  - workflow работает с заглушкой,
  - замена runtime ограничена адаптером.

Издержки: нужны схемы данных и единый формат ошибок.

## Проверка

- UI не вызывает библиотеку инференса напрямую.
- Workflow проходит контрольный сценарий с заглушкой.
- Сбой адаптера даёт определённый результат этапа.
- Свидетельства проверки приложены к карточке реализации.
